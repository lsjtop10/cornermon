# Issue #142 진행자 공지 읽음 처리 (compact)

Issue: #142

## 요구사항
진행자 앱에서 공지함을 열어 읽음 POST가 204로 성공한 뒤에도 메인 화면 공지 배지가 사라지지 않는 버그 수정.

## 원인
`ListBroadcasts`가 `Announcement`만 조회하고 트랙별 `announcement_receipts.read_at`을 매핑하지 않아
TrackAuth 응답의 `readAt`/`isRead`가 항상 `null`/`false`로 내려왔음. 읽음 POST 자체(`MarkNoticeRead`)는
이미 정상 동작.

## 왜 이렇게 했는가
- 새 엔드포인트나 별도 미확인 카운터 컬럼을 만들지 않음 — 이미 개별 receipt와 공지 목록이 있어 중복 상태가 됨.
- 명령(`AnnouncementRepository.Save`)과 조회(`AnnouncementQuerier`)를 CQRS로 분리 — 목록 조회가 상태를
  바꾸지 않는다는 걸 타입으로 보장하고, 트랙-캠프 범위 인가를 조회 유스케이스에 명시적으로 둠.
- 공지×receipt는 `LEFT JOIN` 단일 쿼리로 — 공지 N건당 receipt 개별 조회(N+1)보다 정확한 스냅샷.
- 관리자 개인별 읽음 상태, 진행자 임의 캠프 조회 정책 변경은 범위 밖으로 명시적으로 제외 (Issue #142 요구와 무관).
