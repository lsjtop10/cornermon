## 요구사항

QR 배지 스티커를 PDF로 내보낼 때 용지 크기(A4 고정)와 QR 코드 크기(110px 고정)가
하드코딩되어 있어 조절할 수 없다. 라벨 프린터 등 다양한 용지에 대응하기 위해 용지
크기·QR 크기를 조절 가능하게 하고, 배지 1장씩 개별 이미지로도 내보낼 수 있어야 한다.

- 용지: 프리셋(A4/Letter) + 커스텀(mm 직접 입력, 라벨 프린터 대응)
- QR 크기: 프리셋 + 커스텀. PDF는 가로 길이(mm), 이미지는 해상도(px)

## 유즈케이스

| 우선순위 | 유즈케이스 | 설명 |
| --- | --- | --- |
| P0 | 용지 크기를 골라 스티커 시트 PDF 내보내기 | A4/Letter/커스텀 mm |
| P0 | QR 크기를 골라 스티커 시트 PDF 내보내기 | 프리셋/커스텀 mm |
| P1 | 배지를 1장당 1개 PNG 이미지로 내보내기 | 해상도 프리셋/커스텀 px |

## 설계

- `badge_export_options.dart` (신규): `BadgeExportFormat`(pdfSheet/images),
  `PaperSizePreset`(a4/letter/custom) → `PdfPageFormat` 변환, QR 크기 프리셋 상수.
  기존 UI 컨트롤(`AppDropdown`)과 숫자 입력 필드로 구성.
- `badge_sticker_pdf.dart`: `buildBadgeStickerPdf`에 `pageFormat`, `qrSizeMm` 파라미터
  추가 (기본값 A4/기존 크기 상당으로 하위 호환).
- `badge_sticker_image.dart` (신규): `barcode` 패키지의 `Barcode.qrCode().make()`가
  반환하는 `BarcodeBar` 사각형을 `image` 패키지 `Image`에 직접 채워 PNG로 인코딩한다.
  둘 다 순수 Dart로, 플랫폼 채널(Printing.raster 등) 없이 유닛 테스트 가능 — 기존
  `badgeExportControllerProvider`처럼 `Printing`/`file_saver` platform mock 없이 바로
  테스트 가능한 걸 재사용 우선순위로 택함.
- `pubspec.yaml`: `image`, `barcode`는 이미 `pdf`/`excel`의 전이 의존성 — 코드에서 직접
  import하므로 기존 관례(`collection`, `uuid` 등)대로 direct dependency로 승격.
- `badge_controllers.dart`의 `BadgeExportController`: 옵션(형식/용지/QR크기)을 인자로
  받아 PDF 또는 이미지 여러 장을 생성 후 저장/공유. 이미지 여러 장 공유는 기존
  `track_pin_export_controller.dart`처럼 `ShareParams(files: [...])`로 다중 파일 지원.
  이미지 다중 저장은 `file_saver`가 단일 파일만 지원하므로 `archive`(이미 `excel`의
  전이 의존성)로 zip 묶어 1개 파일로 저장.
- `badge_precreate_screen.dart`: 내보내기 옵션(형식/용지/QR 크기) 선택 UI 추가.

## 왜 이렇게 했는가

- `Printing.raster`로 이미지 래스터화하는 대신 `barcode`+`image` 조합을 택함: 플랫폼
  채널이 필요 없어 유닛 테스트가 가능하고, 이미 프로젝트에 전이 의존성으로 들어와
  있어 새 패키지 추가가 필요 없음.
- 이미지 개별 파일 대신 zip 저장: `file_saver`가 다중 파일 저장 API를 제공하지 않음.
  `archive`도 이미 전이 의존성이라 추가 비용 없음.
