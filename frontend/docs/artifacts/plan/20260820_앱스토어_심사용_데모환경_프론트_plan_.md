# 앱스토어 심사용 데모환경 — 프론트 대응 계획

## 배경 (Context)

`backend/docs/artifacts/plan/20260820_앱스토어_심사용_데모환경_plan_.md`(Phase A)에서
review 전용 백엔드 배포와 `POST /demo/device-registrations`(등록코드 없이 캠프 이름으로
자동승인) 엔드포인트를 정의했다. 그 계획의 Phase B가 프론트 몫으로 범위 밖 처리되어 있는데,
이 문서가 그 Phase B다.

### 검토했다가 기각한 방향

**등록코드를 "데모 코드"로 재활용하는 안**: 애초 구상은 특정 코드값을 입력하면 그 값으로
데모 백엔드 라우팅과 데모 캠프 매칭을 동시에 처리하는 것이었다. 그런데 백엔드 최종 설계가
등록코드 개념 자체를 버리고(캠프를 등록코드가 아닌 이름으로 서버가 미리 알고 있음)
`DemoDeviceRegistrationRequest`에 `registrationCode` 필드가 없어지면서, 라우팅 근거로 쓸
코드값이 사라졌다. 기각.

**상시 노출 "체험하기" 버튼**: 등록 화면에 코드 입력과 나란히 버튼을 두는 안. 심사관에게는
직관적이지만, 진행자 앱은 실제 캠프 스태프가 상시 사용하는 화면이라 실캠프 운영 중 실수로
누를 오염 경로가 생긴다. 또한 이 기능은 심사용으로 한 번 쓰고 버리는 게 아니라 신규 스태프
온보딩/연습용으로도 유효하므로, "알고 있는 사람만 찾는" 형태가 더 맞는다. 기각.

### 최종 방향

**코드가 아니라 UI 진입점으로 라우팅을 결정한다.** 화면에 이미 떠 있는 정적 요소(아이콘/
캡션 텍스트)에 제스처를 얹어 데모 백엔드로의 런타임 전환을 트리거한다. 새 UI를 추가하지
않으므로 시각적으로 화면이 바뀌지 않고, App Store Review Notes에 제스처 순서를 텍스트로
안내하면 된다. 같은 기능이 스태프 연습 모드로도 재사용 가능하다.

**제스처는 두 앱 모두 롱프레스로 통일한다.** 탭 N회 카운트 안은 기각 — 카운트 리셋
타이밍/화면 전환 중 탭 씹힘 등 실패 모드가 있고, 진행자 화면은 아이콘을 감싸는 outer
`GestureDetector`(탭-키보드-언포커스용, `HitTestBehavior.translucent`)와 겹쳐 카운트가 덜
셀 위험도 있다. 롱프레스는 `onLongPress` 콜백 하나로 끝나 구현이 단순하고, 두 앱에 같은
제스처를 쓰면 Review Notes도 "[요소]를 길게 누르세요" 한 문장으로 통일된다.

베이스 URL 자체는 여전히 같은 바이너리에 운영/데모 두 값을 컴파일 타임에 함께 심어두고
(`--dart-define`), 어느 쪽을 쓸지만 런타임에 전환한다 — 백엔드 계획서의 "같은 바이너리가
API base URL 두 개를 다 갖고 스위칭한다"는 전제를 그대로 따른다.

## 아키텍처 원칙

- **`apiClientProvider`가 유일한 전환 지점이다.** `frontend/lib/shared/api/client/api_client.dart`가
  이미 `Dio`를 만드는 단일 choke point이므로, 새 인터페이스를 만들지 않고 이 provider가
  `ref.watch`하는 환경 상태 하나만 추가한다. 이 provider를 건드리는 것 자체는 불가피하다 —
  base URL 전환처럼 진짜 횡단 관심사는 새 엔드포인트로 우회할 수 있는 종류의 로직이 아니다.
- **등록 관련 기존 코드는 건드리지 않는다.** `DeviceTrust.requestRegistration`(운영 등록
  플로우)은 그대로 두고, `requestDemoRegistration`을 나란히 추가한다. 응답 처리(토큰 저장,
  상태 반영) 부분만 두 메서드가 공유하는 사설 헬퍼로 뽑는다 — 백엔드 쪽이 등록+즉시승인
  로직을 기존 메서드 재사용으로 구현한 것과 대칭.
- **제스처는 새 위젯이 아니라 기존 정적 위젯에 얹는다.** 새 아이콘/텍스트를 화면에 추가하면
  "체험하기 버튼"과 다를 바 없어진다. `device_pending_screen.dart`의 등록 대기 아이콘,
  `login_screen.dart`의 하단 캡션처럼 이미 항상 떠 있고 지금은 아무 인터랙션도 없는 요소를
  그대로 재사용한다.
- **환경 전환 시 이전 환경의 토큰이 섞이지 않게 한다.** `SecureTokenStore`는 환경 구분 없이
  같은 키(`device_trust_token` 등)를 쓰므로, 데모로 전환하는 시점에 남아있는 값을 지운다 —
  실기기로 두 환경을 오가며 테스트할 때 오염된 토큰으로 엉뚱한 백엔드를 찌르는 걸 방지.
- **히든 진입점은 "몰라야 못 들어간다"지만, 일단 들어간 뒤엔 반대로 눈에 띄어야 한다.**
  롱프레스로 실수 진입할 확률은 낮지만 0은 아니고, 그 상태에서 실캠프 진행자가 못 알아채면
  사고로 이어진다. `MaterialApp.router`의 `builder`에 `DemoEnvironmentBanner`를 얹어 데모
  환경인 동안 모든 화면 최상단에 경고 스트립이 항상 뜨게 한다 — `admin/app.dart`가 이미
  `ConnectionBanner`를 같은 자리(`builder`)에 얹던 관례를 그대로 재사용, 새 패턴을 만들지
  않는다.
- **데모 환경에서 빠져나오는 경로가 앱 전체에서 항상 존재해야 한다.** 관리자 앱은 로그인
  화면 캡션 롱프레스로 이미 왕복 토글이 가능하지만, 진행자 앱은 `_unlockDemoMode`가 편도
  전환이라 로그인 화면을 벗어나면 되돌아갈 방법이 없었다. `DemoEnvironmentBanner` 자체를
  탭하면 즉시 운영으로 전환되게 해서, 두 앱 모두 "화면이 뭐든 상관없이" 탈출 경로가 항상
  같은 자리에 있게 한다.

  ApiEnvironment build() => ApiEnvironment.production; // 앱 시작 시 항상 운영으로 시작

```dart
// api_client.dart — apiClient가 환경을 watch하도록 한 줄 추가
@Riverpod(keepAlive: true)
Dio apiClient(Ref ref) {
  final environment = ref.watch(activeApiEnvironmentProvider);
  final dio = Dio(
    BaseOptions(
      baseUrl: switch (environment) {
        ApiEnvironment.production => AppEnv.apiBaseUrl,
        ApiEnvironment.demo => AppEnv.demoApiBaseUrl,
      },
      // ...기존 timeout 옵션 그대로
    ),
  );
  // ...기존 interceptor 등록 그대로
}
```

`device_pending_screen.dart` — 등록 대기 아이콘(`Icon(Icons.phonelink_lock_outlined)`)에
`onLongPress`를 얹는다. 트리거 시 `activeApiEnvironmentProvider.notifier
.switchTo(ApiEnvironment.demo)` 호출 + 로컬 상태로 `_RegistrationForm`을 "등록코드 입력란이
없고 표시이름만 받는" 변형으로 전환, 제출 시 `requestDemoRegistration` 호출. 바깥의 기존
tap-to-dismiss-keyboard `GestureDetector`(`HitTestBehavior.translucent`)와 중첩되므로
롱프레스가 씹히지 않는지 실기기 확인 필요 — 탭카운트 대비 상태(카운터/타이머)가 없어
충돌 여지 자체가 적다.

`login_screen.dart` — 하단 캡션(`Text('로그인 상태는 안전하게 유지됩니다.')`)에
`onLongPress`로 `ApiEnvironment` 토글을 얹는다. 전환 결과를 `SnackBar`로 짧게 피드백
("심사용 서버로 전환됨" / "운영 서버로 전환됨") — 화면 자체는 안 바뀌므로 최소한의 확인
수단은 필요.

`lib/shared/design_system/widgets/demo_environment_banner.dart`(신규) — `visible`/
`onExitDemo`를 받는 순수 프레젠테이션 위젯(`ConnectionBanner`와 동일한 스타일: 상태를

`MaterialApp.router` `builder`에서 `activeApiEnvironmentProvider`를 watch해 `visible`을
넘기고, `onExitDemo`는 `switchTo(ApiEnvironment.production)`을 호출한다.
