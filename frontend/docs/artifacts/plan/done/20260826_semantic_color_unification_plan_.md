# 컬러코딩 통일화 및 시멘틱 컬러 도입

Issue: #257
PR: #264

## 요구사항

앱 내부 컬러코딩이 화면마다 다른 의미로 쓰인다(관리자 대시보드 안에서도 유휴가 검정/초록으로 다르고, 관리자는 진행중=초록인데 진행자는 진행중=노랑). 항공 계열 시멘틱 컬러(시안=준비완료, 마젠타=시스템 제한, 옐로우=주의, 레드=경고, 그레이=정상, 그린=동작중)를 도입해 앱 전역에서 같은 색이 항상 같은 의미를 갖게 한다. 빨강 남발을 줄이고, 대부분의 정상 상태는 그레이/블랙으로 충분하게 한다.

## 왜 이렇게 했는가

- **IDLE 색 재정의(전면 재설계, 확정)**: `docs/design-system.md` §1.2가 명문화한 IDLE=초록/BUSY=호박을 뒤집었다 — IDLE=그레이(정상), BUSY=초록(동작중). 조/방문 상태도 같은 축(완료=그레이, 진행중=초록).
- **§1.2-b "코너 카드 집계" 예외 폐기**: 이 예외(`--color-quiet` 근흑색 토큰)는 IDLE=초록이던 시절에만 필요했던 우회였다. IDLE이 그레이가 되면서 트랙 단위 색과 코너 집계 색이 저절로 같은 축이 되어 예외 자체가 불필요해졌다.
- **토큰 이름을 색 시멘틱 기준으로 재명명한 이유**: `statusIdle`/`statusBusy`처럼 도메인 상태명을 그대로 딴 이름은 유지하지 않았다 — "BUSY"라는 상태와 "그린(동작중)"이라는 색 의미는 서로 다른 축이라, 상태가 늘어도 토큰 이름이 계속 맞아야 한다. 도메인 상태 → 색 토큰 매핑은 `cornerStatusPresentation()`·`StatusBadge` 같은 소비처 함수 쪽에 둔다.
- **시안(준비완료)/마젠타(시스템 제한) 적용 범위를 최소로 잡은 이유**: 시안은 캠프 목록 PENDING 배지 1곳뿐(대시보드 "프리뷰 카드"는 실측 지표를 보여주는 걸 코드로 확인해 §design-system.md 3.2 서술이 낡은 것으로 판단, 적용 대상에서 제외). 마젠타는 "관리자가 정한, 진행자가 못 바꾸는 제약값"이라는 의미로 목표시간 텍스트 1곳(대시보드 코너 카드)만 — 확장은 실제 필요가 생기면 진행.
- **파괴적(destructive) 버튼의 빨강 2단계 다운그레이드**: solid 빨강 배경 → 아웃라인으로 다운그레이드. 되돌릴 수 없는 액션(관리자 삭제/회원 탈퇴/기기 회수/캠프 종료)은 아웃라인 유지, 되돌릴 수 있는 액션(강제 로그아웃/세션 종료 — 재로그인하면 원상복구)은 빨강 자체를 뺀 `secondary`로 한 단계 더 낮춤. 실제 "경고"(병목 보더, 하드 블록 모달 등)만 지금처럼 solid 빨강 유지. 계기: 사용자 피드백 "파괴적 액션에 빨간색이 너무 남발돼서 정작 진짜 경고가 안 보인다."
- `success`는 새 `statusActive`(초록)와 값을 통일 — "정상 동작 중"과 "성공적으로 완료됨"은 같은 긍정 개념이며, 기존에도 `success`가 상태색과 의도적으로 통일돼 있었다는 전례를 그대로 이었다.
- `statusNormal`/`statusInactive`를 완전히 같은 회색 하나로 합치지 않고 톤 차이를 유지한 이유: 아이콘뿐 아니라 색 톤으로도 "정상(유휴)"과 "미가동"이 구분돼야 몇 미터 밖 스캔 가독성이 유지된다(§0-4 원칙).
- 코너 카드 집계 로직 중복 제거: `corner_detail_screen.dart`가 `cornerStatusPresentation()`을 안 쓰고 같은 switch를 직접 복사해 갖고 있던 걸 제자리에서 발견해 정리(별도 이슈로 미루지 않음).
- 상태 축이 아닌데 (구)`statusIdle`/`quiet`를 "좋음/짙은 텍스트" 용도로 빌려 쓰던 4곳(QR 스캔 성공 테두리, 방문완료 체크 아이콘, 진행 바 정상색, 더블탭 확인 버튼 텍스트)을 `success`/`textPrimary`로 교체 — 상태 토큰을 일반 피드백 용도로 빌려 쓰는 것 자체가 이번 이슈가 지적한 "컬러 의미 흔들림"의 축소판이었다.
- **후속(2026-08-26, 별도 요청)**: 코너 카드 미가동(트랙 없음, `INACTIVE`) 색을 `statusInactive`(중립 회색) → `statusAlert`(경고색)로 재조정. 트랙이 없어 미가동인 코너는 단순 비활성이 아니라 조치가 필요한 상태라는 판단.
- 뱃지(자기 색 12%/20% 틴트 배경 위 같은 색 텍스트) 실사용 기준으로 신규/기존 토큰 대비를 재점검한 결과, 흰/검 배경 기준으로는 통과해 보이지만 실제 옅은 틴트 배경에서는 WCAG AA 미달인 토큰이 다수 있어 값을 재조정했다(`docs/design-system.md`에 배경 조건별 대비 확인 원칙으로 남김).
