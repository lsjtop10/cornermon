# 진행자 앱 전체 플로우 완성 — 개요 (compact)

## 요구사항
선행 Plan([[프론트엔드_스캐폴딩_아키텍처_plan_20260709]])의 Phase 05(진행자 라우팅+B0~B8
스캐폴딩)가 실제로는 실행된 적이 없어 진행자 화면이 하나도 없는 상태. 라우팅 + SSE 인프라 +
visit provider + 10개 화면(B8 제외) + 테스트 인프라를 처음부터 구현.

## 왜 이렇게 했는가 (사용자와 협의해 확정한 스펙-계약 불일치 처리)
- **B8 트랙 교체 자동전환 미구현**: screen-spec/scenarios는 "재PIN 없이 자동 세션전환"을
  요구하지만 계약상 트랙 교체는 삭제와 동일 처리되어 기존 기기가 `track_deleted` 알림만 받고
  강제로 PIN 재입력(B1)으로 전환됨 — 자동전환에 필요한 이벤트/엔드포인트가 계약에 없어 이번
  Plan에서 B8을 별도 구현하지 않고 기존 강제종료 경로로 흡수, [이슈 #30]으로 분리.
- **B0 승인 자동 감지 불가**: 미승인 기기가 자기 등록 상태를 조회할 API가 없음(관리자 전용 `GET
  /device-registrations`뿐) — 라우터 가드가 `pending` 상태도 PIN 로그인 화면 진입을 허용하고
  "승인받으셨다면 계속하기" 수동 버튼을 둠. 실제 승인 여부는 B1의 PIN 로그인 호출(403
  `DEVICE_NOT_TRUSTED`)이 최종 게이트. 전용 상태조회 API는 [이슈 #32]로 분리.
- **B1 "관리자에게 도움 요청" 링크는 기능 자체를 제거**(백엔드 이슈로 분리하지 않음) — PIN
  잠금 상태에선 어느 트랙인지 확정된 적이 없거나 세션이 이미 무효화돼 열 수 있는 트랙 스코프
  스레드가 구조적으로 없음. 대안 채널을 새로 만들 값어치도 없다고 판단 — 5회 이상 실패 시 관리자
  대시보드에 `lockout_alert`가 이미 자동으로 뜨므로, 그보다 낮은 단계는 잠깐 기다리면 되는
  수준이라 도움 요청 채널이 커버할 실질적 틈새가 없음.
- **API 날짜/시간은 전부 UTC**(문서 상단에 명시, 최초 조사 때 놓쳤다가 사용자 지적으로 확인) —
  `DateTime.difference()`로 계산하는 경과/소요 시간은 변환 없이도 정확하지만, 절대 시각을 사람에게
  보여주는 곳(B6/B7 타임스탬프)은 반드시 `.toLocal()` 후 포맷해야 함.
- 검증 범위는 `flutter analyze` + Riverpod override 기반 자동화 테스트로 한정(사용자 확인) —
  이 환경엔 GUI가 없어 실기기/에뮬레이터 구동이 애초에 불가능.
