# Phase 05 — A1 대시보드 (compact)

## 요구사항
캠프 운영 모드(ACTIVE) 기본 화면: 코너 상태 카드 그리드(정렬 4종·필터 5종), 상단 요약 바(완주율·
미완주 조 수·경과시간·안읽은 다이렉트), A2/A2B/A10 진입점. SSE 연동은 범위 밖 — 1차 구현은
pull-to-refresh/재진입 재조회로만 최신화.

## 왜 이렇게 했는가
- 코너 카드의 "평균/편차/표본수" 문구는 계약 공백이 있었음: 평균·표본수는 신설된
  `CornerResponse.cornerMetric`에서, 편차는 여전히 `bottleneckRanking` 조인이 필요(다른 스키마라
  A12 리포트의 동일한 갭과는 별개) — 편차 데이터가 없으면 괄호 부분만 생략.
- "안읽은 다이렉트 메시지 수"는 전용 `unread-count` 엔드포인트가 아직 미구현(501, Issue #69)이라,
  `09`가 확정한 `trackDirectSummariesProvider`의 파생값을 합산하는 방식을 그대로 재사용(신규
  N+1 호출을 만들지 않음).
- "미완주 조 수"는 `totalGroups - finishedGroupCount`로 정의 — "지금 이 순간 코너에서 활동 중인
  조"라는 좁은 지표가 아니라 "아직 완주 못한 조 전체"를 세는 게 목적(남은 일감 파악용)이라 의도적
  선택. 라벨도 "진행중 조"에서 "미완주 조"로 변경해 혼동 소지 제거(PR #192 후속 논의).
- "코너번호순" 정렬은 `Corner.name`이 "코너 1" 같은 자유 텍스트라 정규식으로 숫자를 추출 — 숫자가
  없는 이름(예: "미술코너")은 서버 응답 순서(생성 순서로 추정)로 폴백.
- 카드 색상 3분류는 기존 `StatusBadge`(진행자 앱의 "방문 상태" 의미론, idle=녹색/busy=호박색)를
  재사용하지 않음 — 이 화면의 "코너 운영 상태"는 BUSY=정상=녹색이라 색 배정이 정반대로 얽혀 있어
  카드 전용 매핑을 새로 둠.
