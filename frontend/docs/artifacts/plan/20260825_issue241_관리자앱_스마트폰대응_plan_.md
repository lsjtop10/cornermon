Issue: #241

## 원 요구사항

현장 운영 관리자가 태블릿만 보면서 모니터링을 수행하기는 어려우므로, 관리자 앱이 스마트폰
폭에서도 동작해야 한다.

## 범위 확정 (사용자 확인 완료)

- **모니터링 화면만 대응**: 대시보드, 조 현황, 조 상세, 코너 상세, 기기 관리, 리포트.
  셋업 마법사/배지 사전생성/관리자 계정 관리/세션 관리/메시지/감사 로그/설정은 이번 범위
  제외 — 태블릿·PC 전용으로 유지한다(스마트폰에서 접근은 되지만 반응형 작업은 안 함).
- **사이드바**: 기존 축소 모드(64px, `adminSidebarExtendedProvider`)를 그대로 재사용한다.
  새 하단 탭바/Drawer는 만들지 않고, 폭 breakpoint에 따라 이 기존 모드로 자동 전환만 추가한다.
- **로그인/캠프 목록 화면**: "모니터링 화면"은 아니지만 그 진입 경로다. 여기가 좁은 폭에서
  깨지면 모니터링 화면 대응 자체가 무의미해지므로, 실제로 오버플로가 나는 지점만 최소
  수정한다(전체 반응형화는 안 함).

## 코드베이스 조사 결과

- **이미 대응돼 있어 변경 불필요**: `group_list_screen.dart`/`group_detail_screen.dart`는
  이미 `LayoutBuilder`로 카드 폭·그리드 열 수를 계산 중. 대시보드 코너 카드 그리드는
  `SliverGridDelegateWithMaxCrossAxisExtent`라 폭에 자동 적응. 코너 상세의 트랙 테이블은
  이미 `SingleChildScrollView(scrollDirection: horizontal)`로 감싸져 있음.
- **손대야 함**: `AdminScaffold`/`AdminSidebar`(고정폭 셸 — 240/64px 둘 다 좁은 폭 전제 없음),
  `dashboard_screen.dart`의 `_SummaryBar`(4분할 Row/Expanded — "iPad 가로가 1차 타겟, 세로
  모드는 최적화 대상 아님"이라는 기존 주석과 정면으로 충돌하는데, 이슈 241이 그 전제를
  갱신하는 요청이므로 이번에 덮어쓴다), `login_screen.dart`(카드 `width: 400` 고정 — 400px
  미만 폭에서 오버플로), `camp_list_screen.dart`(AppBar에 라벨 있는 버튼 4개가 나란히 있는
  Row — 좁은 폭에서 오버플로).
- **확인만 필요(고정폭 이슈를 코드 조사로 못 찾음)**: `device_manage_screen.dart`/
  `_device_registration_row.dart`는 대체로 `Expanded`/`ListView` 기반이라 이미 유연해
  보임. `report_screen.dart`는 얇은 shell이고 실제 내용은 `widgets/report_tabs.dart` 등
  하위 트리 — 이번 조사에서 전부 훑지 않았다. 두 화면 다 실기기/에뮬레이터 실측 후 발견되는
  지점만 국소 수정한다.

## 아키텍처 원칙

- 새 반응형 프레임워크·패키지 도입 안 함. `LayoutBuilder`/`MediaQuery`로 충분한 규모.
- Breakpoint는 상수 하나로 관리한다(`AppDimensions`) — 화면마다 매직넘버 반복 금지.
- 사이드바는 "축소 모드"라는 기존 개념을 확장만 한다(폭 기반 강제 축소 파라미터 추가).
  새 네비게이션 패턴(하단 탭/Drawer)은 만들지 않는다.

## Phase 1: 진입 경로(로그인/캠프 목록) 오버플로 수정

**파일**: `login_screen.dart`, `camp_list_screen.dart`

- 로그인: `Container(width: 400)` → `ConstrainedBox(maxWidth: 400)`로 교체해 400px 미만
  폭에서는 카드가 자연스럽게 화면 폭까지 줄어들게 한다.
- 캠프 목록: AppBar의 라벨 있는 버튼(QR 배지 관리/새 캠프 시작)을 `phoneBreakpoint` 미만
  에서 `AppButtonVariant.iconOnly`로 전환한다(기존 variant 재사용, 새 위젯 없음).

## Phase 2: 대시보드 `_SummaryBar` 2열 대응

**파일**: `dashboard_screen.dart`

`phoneBreakpoint` 미만이면 4개 타일을 Row/Expanded 대신 `GridView.count(crossAxisCount: 2)`
로 배치한다(이상 폭에서는 기존 Row 그대로 유지). 기존 주석에 남아 있던 "세로 모드는
최적화 대상 아님"이라는 결정을 이슈 241 요청으로 갱신한다는 점을 코드 주석에도 남긴다.

## Phase 3: 조 현황/조 상세/코너 상세 — 실측만

코드는 이미 반응형(LayoutBuilder, 가로 스크롤 테이블)이라 변경 없이 360~430px 폭에서
실기기/에뮬레이터로만 확인한다.

## Phase 4: 기기 관리/리포트 — 실측 후 국소 수정

사전 조사에서 명백한 고정폭 문제를 찾지 못함 — 실기기 확인 후 오버플로 발견 시 그
지점만 `Wrap`/`Expanded`로 국소 수정한다(발견 전에는 스니펫 없음).
