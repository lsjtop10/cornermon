> 선행 문서: `10_a12_report.md`(요약/코너별/조별 3탭 기존 구현) — 그 문서 §00 overview §4 결정으로

> 뒤 이어서 구현한다. 대상 독자: 1~2년차 프론트엔드 개발자, 예상 소요 5~7시간.

> 화면에 노출하지 않음).

## 0. API 근거 (읽고 시작)

- `GET /camps/{campId}/reports/current` 등 4개 엔드포인트가 공통으로 쓰는 `CampReportResponse`에
  `trackStats: TrackStatsResponse[]`, `timeline: TimelineStatsResponse`,
  `operationalStats: OperationalStatsResponse`가 추가됐다(`api/swagger.yaml:236-244`).
- 스키마 정의(`api/swagger.yaml`):
  - `TrackStatsResponse`(`:887`): `trackId`, `trackNo`, `handledVisitCount`, `avgDeviationSeconds`,
    `manualVisitRatio`.
  - `TimelineStatsResponse`(`:815`): `buckets: TimelineBucketResponse[]` — `bucketStart`(date-time),
    `inProgressCount`, `cumulativeCompleted`. 5분 버킷.
  - `OperationalStatsResponse`(`:731`): `pinLoginSuccessCount`/`pinLoginFailureCount`/
    `deviceRequestCount`/`deviceApprovedCount`/`deviceRejectedCount`/`deviceRevokedCount`(모두
    integer) + `adminOperationCounts: AdminOperationCountResponse[]` +
    `trackDirectMessageCounts: TrackMessageCountResponse[]` +
    `announcementReadStats: AnnouncementReadStatResponse[]`.
  - `CampSummaryStatsResponse.exceptionApprovalCount`는 기능 삭제로 **항상 0** — 이번 작업에서
    화면에 렌더링하지 않는다(사용자 결정, 오해 소지 방지).
- **[해소됨] §0-1 `AdminOperationCountResponse`/`AnnouncementReadStatResponse` 필드 구성**
  (`api/swagger.yaml:17-26`, `:55-66` 직접 확인):
  - `AdminOperationCountResponse`: `adminId`(uuid), `adminName`, `count`.
  - `AnnouncementReadStatResponse`: `announcementId`(uuid), `announcementContent`, `readCount`,
    `totalRecipients`.
- `TrackStatsResponse`는 이미 `frontend/packages/cornermon_api_gen/lib/src/model/track_stats_response.dart`로
  생성돼 있다. `TimelineStatsResponse`/`OperationalStatsResponse`(및 그 하위 스키마)는 아직
  생성된 모델이 없다 — **`api/swagger.yaml` 기준 전체 재생성 필요**(부분 재생성 불가,
  `10_a12_report.md` H-12 메모와 동일한 이유). 재생성 후 `dart run build_runner build`(gen
  패키지 내부, built_value_generator)까지 실행해야 직렬화 코드에 반영된다.

## 2. 객체 정의

### 2.1 `domain_aliases.dart` 확장 (신규 alias 추가)

```dart
// lib/shared/api/domain_aliases.dart
typedef TimelineStats = TimelineStatsResponse;
typedef TimelineBucket = TimelineBucketResponse;
typedef OperationalStats = OperationalStatsResponse;
typedef AdminOperationCount = AdminOperationCountResponse;
```

생성된 클라이언트 타입명을 직접 쓰지 않기 위함.

### 2.3 트랙별 통계 섹션

```dart
// lib/admin/features/report/widgets/track_stats_section.dart (신규)
/// 트랙마다 1행 — analytics-model.md §1.3. corner_stats_row.dart와 동일하게 DataTable +

// lib/admin/features/report/widgets/track_stats_row.dart (신규)

```

#### 2.3.1 [해소됨] `TrackStatsResponse.manualVisitRatio` 스케일

`backend/internal/infrastructure/web/report_handler.go:216-224`(`mapReport`의 트랙 순회 블록)를
코드 리딩(읽기만, backend 수정 아님)으로 확인: `manualVisitRatio := float32(tr.ManualCount) /
float32(tr.CompletedCount) * 100`로 **이미 0~100 퍼센트 스케일**이다 —
`CampSummaryStatsResponse.manualVisitRatio`와 동일 규칙. `${stats.manualVisitRatio.round()}%`로
그대로 렌더링한다(추가 ×100 금지).
