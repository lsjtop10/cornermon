# 기기 등록 코드(campId 해시, Crockford Base32) 사전 생성 및 등록 플로우 개선 (compact)

Issue: #108 (백엔드) / 선행 #107(설계 논의) / #109(프론트)

> **후속 변경**: 이 설계(campId 해시 기반 등록 코드)는 이후 보안 취약점(campId가 비밀이 아니라
> 역산 가능)이 발견되어 `20260819_기기등록코드_랜덤생성_plan_.md`로 대체되었다. 아래는 최초
> 도입 당시의 요구사항/결정 기록.

## 요구사항
진행자 앱에 campId를 사전 안내받을 채널이 없어(#107), "관리자에게 받은 등록 코드"라는 API 계약에
없던 개념을 구현해야 했음. `POST /device-registrations`가 campId 원문 대신 등록 코드를 받도록,
기기 기종·표시 이름 필드도 함께 추가.

## 왜 이렇게 했는가 (당시 결정, #107 논의 결과)
- 등록 코드는 campId 원문이 아니라 **campId를 해싱한 코드**로 발급, Camp 생성 시점에 사전 계산해
  컬럼 저장(요청마다 재계산 금지, O(1) 조회) — 이후 이 "해싱=비밀"이라는 전제 자체가 취약점으로
  드러나 랜덤 생성으로 교체됨(위 후속 변경 참고).
- `workflow/Collaborate.md`의 "프론트가 계약 변경 PR을 먼저 연다" 원칙의 예외 — 계약 내용이 이미
  #107에서 레포 오너가 확정했으므로, 백엔드가 먼저 구현하고 계약을 갱신한 뒤 프론트(#109)가
  참조하는 순서로 사용자 확인 하에 합의.
- Crockford Base32는 단방향 발급 전용이라 표준 `encoding/base32`로 인코딩만 하고, 모호 문자
  디코딩 보정은 구현하지 않음 — campId 복원은 DB 컬럼 매칭으로 하지 디코딩으로 하지 않으므로.
