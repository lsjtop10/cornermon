# 기기 등록 코드 생성 방식 개선: campId 해싱 → 랜덤 생성 (compact)

Issue: #217 (관련 이전 설계: `20260717_기기등록코드_campid해시_plan_.md`)

## 요구사항
등록 코드가 `campId`의 결정적 함수(SHA-256 해시)라서, `campId`(비밀 아님, `GET /camps` 응답에
노출됨)를 안다면 오프라인에서 동일 해시를 재계산해 등록 코드를 얻어낼 수 있는 취약점(#217).

## 왜 이렇게 했는가
- 등록 코드를 campId의 함수로 계산하지 않고 Camp 생성 시점에 `crypto/rand`로 직접 무작위 생성 —
  코드 길이(8자 Crockford Base32, 40비트)는 기존과 동일하게 유지해 DB 컬럼 크기·API 계약·
  프론트 UX에 영향 없도록 함.
- 재시도(충돌 처리) 로직은 범위 밖으로 명시 제외 — 40비트 공간에 캠프 생성 빈도를 고려하면
  무시 가능한 리스크이고, 기존 해시 기반 설계도 동일한 전제였으므로 새로 생기는 리스크가 아님.
- `crypto/rand.Read` 실패는 OS 엔트로피 고갈 등 프로세스 자체가 불안정한 상황이므로 panic으로
  즉시 드러냄(기존처럼 무입력·무의존 순수 함수 유지).
